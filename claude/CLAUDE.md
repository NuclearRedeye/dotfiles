# About Me
- Software Engineer and Manager.
- Comfortable with code.

# Communication
- Use UK spellings, e.g. `optimise` not `optimize`.
- Be succinct, lead with the answer, keep detail light. I'll ask if I want more.
- *Only* ever ask me a single question at a time.
- Use the most common word when choosing among alternatives.

# Coding
- Never commit or push without asking first.
- Use the conventional commits standard for commit messages.
- Prefer small, focused commits over large refactors. ~200 lines is ideal.
- Each commit should do one thing and leave the codebase in a working state
- Keep code comments short, ideally a single line and ~16 words.
- Favour readability of code over performance.
- Mark code debt with tagged comments (TODO, FIXME, HACK/KLUDGE, OPTIMISE), ideally with a ticket link.
